[BUG REPORT]
Sistema de checkout com múltiplas falhas críticas.

PROBLEMAS IDENTIFICADOS:

1. SEGURANÇA - XSS no campo de cupom:
   - Input: <script>alert('xss')</script>
   - Sistema executa o script
   - Não há sanitização de entrada

2. INTEGRAÇÃO - Gateway de pagamento retorna erro intermitente:
   - POST /api/payment/process retorna 504 Gateway Timeout em 30% dos casos
   - Clientes são cobrados mas pedido não é criado
   - Logs: "Connection pool exhausted" no Postgres

3. LÓGICA DE NEGÓCIO - Race condition em cupons de desconto:
   - Cupom "PROMO10" (limite: 100 usos)
   - Sistema permitiu 147 usos
   - Verificação de limite não é atômica

4. UX - Loading infinito após timeout:
   - Se pagamento demora > 30s
   - Tela fica com spinner eternamente
   - Usuário não sabe se pagamento foi processado

IMPACTO:
- 150+ clientes afetados na última semana
- Perda estimada: R$ 15.000 em cupons indevidos
- 45 tickets de suporte abertos
- Rating do app caiu de 4.5 para 3.2 estrelas

[OUTPUT ATUAL]
Como um usuário do sistema de checkout, eu quero que o processo de pagamento funcione de forma segura e eficiente, para que eu possa concluir minhas compras sem problemas e sem riscos de segurança.

Título: Sistema de checkout seguro e eficiente

Descrição:
Como o sistema de checkout, eu quero garantir a segurança contra XSS, resolver erros de integração com o gateway de pagamento, evitar race conditions em cupons de desconto e melhorar a experiência do usuário durante o pagamento, para que os clientes possam realizar suas compras sem interrupções ou riscos.

=== CRITÉRIOS DE ACEITAÇÃO ===

A. Segurança - Proteção contra XSS:
- Dado que um usuário insere um cupom no campo de entrada

C. Lógica de Negócio - Prevenção de race condition em cupons:
- Dado que um cupom "PROMO10" está sendo utilizado
- Quando múltiplos usuários tentam usar o cupom simultaneamente
- Então o sistema deve garantir que o limite de 100 usos não seja ultrapassado
- E deve registrar o uso de cada cupom de forma atômica
- E deve exibir uma mensagem de erro se o limite for atingido

D. UX - Melhoria na experiência de loading:
- Dado que um pagamento está em processamento
- Quando o tempo de espera ultrapassa 30 segundos
- Então o sistema deve exibir uma mensagem informando que o pagamento está em andamento
- E deve permitir que o usuário cancele a operação
- E não deve ficar com o spinner eternamente

Segurança - Sanitização de entrada:
- Implementar sanitização de entrada no campo de cupom
- Usar bibliotecas de segurança para evitar XSS

Integração - Tratamento de timeout:
- Implementar retry com backoff exponencial para falhas no gateway
- Monitorar e otimizar o pool de conexões do Postgres

Lógica de Negócio - Verificação atômica:
- Implementar verificação de limite de uso de cupons com transações atômicas

UX - Feedback ao usuário:
