A. Segurança - Proteção contra XSS:

- E não deve cobrar o cliente se o pedido não for criado
- E deve registrar erros de timeout nos logs

C. Lógica de Negócio - Limite de uso de cupons:
- Dado que o cupom "PROMO10" tem um limite de 100 usos
- Quando um cliente tenta usar o cupom
- Então o sistema deve verificar o limite de forma atômica
- E não deve permitir mais de 100 usos do cupom

D. UX - Feedback de pagamento:
- Dado que o pagamento demora mais de 30 segundos
- Quando o sistema não recebe resposta do gateway
- Então deve exibir uma mensagem de erro ao usuário
- E não deve deixar o spinner carregando indefinidamente

=== CRITÉRIOS TÉCNICOS ===

Segurança - Sanitização de entrada:

Integração - Tratamento de timeout:

Lógica de Negócio - Verificação atômica:
- Usar transações para garantir que a verificação e a aplicação do uso do cupom sejam atômicas

UX - Mensagens de feedback:
- Implementar lógica para exibir mensagens de erro e status de pagamento ao usuário

1. XSS no campo de cupom devido à falta de sanitização

=== CRITÉRIOS DE ACEITAÇÃO ===

A. Conflito de Dados - Merge correto:
- Dado que dois usuários A e B editam a mesma tarefa offline

- Então o sistema deve aplicar um mecanismo de merge que preserve as alterações de ambos
- E o usuário A deve ser notificado se sua alteração foi sobrescrita

- Dado que um usuário anexa um arquivo grande (50MB) e inicia o upload
- Quando a conexão é perdida durante o upload
- Então o sistema deve retomar o upload a partir do ponto de falha
- E o usuário deve ser notificado se o upload falhar após várias tentativas

C. Ordenação - Aplicação correta de operações:
- Dado que um usuário cria, edita e deleta uma tarefa offline
- Quando o sistema sincroniza as operações
- Então as operações devem ser aplicadas na ordem correta
- E o sistema deve respeitar os timestamps client-side

D. Memória - Evitar crashes:
- Dado que um usuário tem 1.500 operações pendentes para sincronizar
- Quando o sistema tenta sincronizar todas as operações de uma vez
- Então o sistema deve processar as operações em lotes para evitar sobrecarga de memória
- E o aplicativo não deve crashar durante a sincronização

=== CRITÉRIOS TÉCNICOS ===

Sincronização - Processamento em lotes:
- Implementar lógica de sincronização em lotes de 100 operações por vez
- Monitorar uso de memória e implementar fallback para evitar crashes
